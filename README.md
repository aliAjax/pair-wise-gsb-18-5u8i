# 根管治疗病例复核台（牙体牙髓科）

替代纸质签字的根管病例登记与复核工具：住院医师按牙位逐根登记工作长度与器械清点，提交结案时系统自动检查记录齐全性；主诊医生可逐颗复核、退回并写明原因，学员补齐后生成新版本，历史审批结果永久可查。未通过的病例不进入完成统计。

## 技术栈与约束

React + Vite + TypeScript + 原生 CSS，**不新增任何依赖**；数据仅存浏览器 `localStorage`，无后端、无网络请求。

## 分层结构

代码按「病例资料 / 复核规则 / 页面 / 浏览器存储」四个目录分离，互不越界：

- `src/data/` — 病例资料：领域类型（`types.ts`）、阶段/角色常量与空白病例工厂（`constants.ts`）、演示种子数据（`seed.ts`）
- `src/rules/` — 复核规则：
  - `checks.ts` 提交结案的齐全性检查（阻断项 / 提醒项）与规则目录
  - `stats.ts` 病例状态派生（草稿/待复核/已通过/已退回）与完成统计口径
- `src/pages/` — 页面：`CaseList`（列表筛选）、`CaseEdit`（登记/补齐）、`CaseDetail`（详情与主诊复核、版本时间线）、`Stats`（完成统计）、`Rules`（规则说明）
- `src/storage/` — 浏览器存储：`store.ts` 是唯一接触 `localStorage` 的模块，负责草稿、版本快照、审批落库与数据初始化
- `src/components/`、`src/utils/` — 通用 UI 与格式化工具

## 核心业务规则

1. 登记字段：患者代号、FDI 牙位、诊断、根管数、**逐根根管名称与工作长度（mm）**、主尖锉、术前/术后器械清点与一致确认、治疗阶段、充填方式、备注。
2. 仅「根管充填（结案）」阶段允许提交结案；提交时运行全部规则：
   - 阻断项：代号格式、牙位合法（11–48 / 51–55）、根管数与明细行数一致、根管命名不重复、工作长度逐根已填、阶段为结案、主尖锉逐根登记、充填方式、器械清点齐全且确认一致；
   - 提醒项：工作长度超出 8–32mm 常规范围时提示但不阻断。
3. 每次提交生成不可变版本快照（含当时规则检查结果）。主诊医生可通过或**退回（原因必填）**；退回后学员补齐再提交得到新版本，旧版本及其审批意见/退回原因在详情页时间线永久可查。
4. 完成统计只统计**最新版本复核通过**的病例；草稿、待复核、已退回均不计入。

## 本地运行

```bash
npm install
npm run dev      # 开发端口 5104
npm run build    # 类型检查 + 构建
```

首次打开自动写入 4 条演示病例（已通过 / 已退回 / 待复核 / 草稿各一），页头「重置演示数据」可恢复。可在右上角切换「住院医师 / 主诊医生」身份体验完整闭环。
